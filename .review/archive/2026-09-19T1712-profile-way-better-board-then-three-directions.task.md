## Why

Thomas saw today's five directions (continuous, trimmed, quoted, docked, live)
and said: "nope, not really what I am going for, I want it to look way way
better." The last two rounds optimised inside one idea (the lattice frame as the
page). That idea is not the problem to refine; the bar is.

Constraints that stay: GitHub renders only Markdown, sanitised HTML and images
(SVG as image, no script); readable on a phone (19 Sep measurement: SVG text at
0.30x, keep type legible); blue links; dark field; Atrium leads; BlueBand at the
same weight as the rest; no dots under his name; far fewer words. Everything he
builds is meant to connect back into his own software (Atrium), so the page
should read as part of that system.

## Do, stop after step 3

1. **Reference board.** Find the 15 to 20 best-looking GitHub profile READMEs
   and portfolio pages you can (search GitHub's awesome-profile lists, awwwards,
   and designer and engineer portfolios), plus the *Tron: Legacy* / GMUNK frames
   in `Atlas/Projects/Atrium/References/`. For each: one screenshot and one line
   on what specifically makes it look good (type, rhythm, motion via GIF/APNG,
   restraint, imagery). Save as `design/reference-board/` with an index page.
2. **Three directions that differ in kind, not degree.** For example: one
   typographic and nearly imageless; one built around animated imagery (APNG or
   GIF of the real lattice moving, since motion is allowed in images); one that
   treats the page as an Atrium interface with docked readouts. Each built with
   real content and rendered with `make page` at desktop and phone.
3. **Put all three next to the three reference items each borrows from**, so
   Thomas can see the intent as well as the result.
